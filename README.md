# World Divide

A real-time strategy game in the spirit of C&C Generals Zero Hour, built in Unreal Engine 5.6. Gameplay logic is C++; content and UI go in Blueprint and data assets. Nothing is taken from Generals itself: no names, art, audio, UI or code.

## Requirements

- Unreal Engine 5.6
- Visual Studio 2022 with the "Game development with C++" workload
- Git LFS (`git lfs install` once per machine) — all `.uasset`/`.umap` files live in LFS and are lockable

## Getting started

1. Clone, then right-click `WorldDivide.uproject` → *Generate Visual Studio project files*, or just open the `.uproject` and let it build.
2. The editor opens `L_TestMap`. Press **Play**.

Command-line build:

```
"<UE_5.6>\Engine\Build\BatchFiles\Build.bat" WorldDivideEditor Win64 Development -Project="<repo>\WorldDivide.uproject" -WaitMutex
```

## Controls

| Input | Action |
|---|---|
| WASD / arrow keys / screen edge | Pan camera |
| Mouse wheel | Zoom |
| Q / E, or drag with middle mouse | Rotate camera |
| Left click / left drag | Select own units (Shift adds or toggles); a click on an own building selects that building |
| Delete, or the HUD's cancel button | Cancel the own construction site under the cursor, or else the selected one, for a refund; with a production building selected, cancel the last entry in its queue |
| Right click | Move, attack when on an enemy unit or building, harvest when on a supply source, or resume an own construction site with builders (Shift queues); with a production building selected, set its rally point |
| X | Stop |
| J, then left click | Attack-move: walk to the clicked spot, stopping to fight enemies that come into range on the way (Shift queues and keeps attack-move armed); right click or Esc cancels |
| 1–9 | With a builder selected: place the n-th building on its list; the builder walks there, places it and builds it. With `rts.DebugBuild 1` in the console and no builder selected: place the n-th building of your faction directly |
| 1–9, or a click on its menu in the HUD | With a production building selected: queue the n-th unit or upgrade; a click on a queued entry in the HUD cancels it for a refund |
| Left click / right click or Esc | While placing: build (Shift queues it and keeps placing) / cancel (Esc also stops PIE in the editor) |

## Layout

| Path | Contents |
|---|---|
| `Source/WorldDivide/Data` | `URTSEntityData` / `URTSUnitData` / `URTSBuildingData`: every unit and building is a data asset (mesh, health, weapon, speed or footprint, power output and draw and whether its weapon needs power, cost, build time, prerequisites, faction); `URTSHarvesterData` adds load size, gather time and search radius, `URTSBuilderData` the buildings a builder can construct, and a building can take supply deliveries, spawn a unit when completed and list the units it produces and the upgrades it researches; `URTSUpgradeData` is a one-time research that multiplies a stat (weapon damage or max health) of the units and buildings it lists; `URTSWeaponData` holds range, damage and reload; `URTSFactionData` lists what a faction can build and whether it uses power |
| `Source/WorldDivide/Combat` | `URTSHealthComponent` (replicated health, death), `IRTSTargetable` (team, health and footprint shared by units and buildings) and the server-side `URTSWeaponComponent` (targeting, instant-hit fire) |
| `Source/WorldDivide/Commands` | `FRTSCommand`, formation layout and server-side dispatch |
| `Source/WorldDivide/Buildings` | `ARTSBuilding` (constructs over its build time, cuts the navmesh, inert until complete), the server-side `URTSBuilderComponent` that runs a builder's Build order, the `URTSProductionComponent` holding a building's build queue of units and upgrades and its rally point, the shared grid and placement rules, and the local placement ghost |
| `Source/WorldDivide/Economy` | The map-placed `ARTSSupplySource` (finite supplies, cuts the navmesh like a building) and the server-side `URTSHarvesterComponent` that runs a harvester's gather and delivery loop |
| `Source/WorldDivide/Units` | `ARTSUnit` (light pawn, no Character), its AI controller, the map-placed `ARTSUnitSpawner`, and `RTSApproach` (picks a reachable spot around a building or supply source footprint) |
| `Source/WorldDivide/Player` | Camera pawn, player controller (input, selection, orders, building placement) and HUD (health of selected units and of the hovered or selected building, a cancel button for a selected construction site, credits and power, the selected builder's build menu with costs, the selected production building's menu with researched upgrades marked done, queue and rally point) |
| `Source/WorldDivide/Core` | Game mode (team and faction assignment, starting credits, team start spots), player state (team, faction, credits, the power of its completed buildings, its researched upgrades), and `URTSSettings` (default faction and ghost material, set in `Config/DefaultGame.ini`) |
| `Tools/Editor/setup_testmap.py` | Builds the placeholder unit, harvester, builder, weapon, upgrade, building (power plant, tower, supply depot, barracks, vehicle factory) and faction data assets, the placement ghost material and `L_TestMap` with a supply source and two builders by each base, saving only what differs from the script |
| `Tools/Editor/placeholder_art.py`, `Art/Source/Placeholder` | Free CC0 stand-in models (Kenney, Quaternius; see `CREDITS.md` there) that setup imports for every unit, building, wall and supply source, each tinted towards its team colour |

Every player order is an `FRTSCommand` sent through `ARTSPlayerController::Server_IssueCommand` and executed only on the server, so singleplayer already runs the multiplayer code path. Units and buildings are always relevant for now; fog of war will decide relevancy later.

Buildings snap to a 100 cm grid. The client's ghost and the server run the same placement check (no overlap with units, buildings or obstacles; footprint on the navmesh), which is why clients keep a navmesh too (`bAllowClientSideNavigation`). Builders place buildings: a `Build` order sends the builder to a spot just outside the footprint, where it places the building (after the same checks) and constructs it for as long as it stays. The building is paid when it is ordered, also when queued with Shift, and refused when the player cannot afford it or lacks one of its prerequisites; an order that ends before its building is placed (stopped, replaced, unreachable or blocked spot, builder killed) is refunded in full. Own units standing on the spot when the builder arrives step aside to the nearest free spot outside the footprint, then pick up their own orders again; the builder places the building once the spot is clear, or gives up after 5 seconds. That is why a builder's ghost stays green over own units, while the debug ghost, placing without a builder, turns red over any unit. An enemy unit, a building or an obstacle on the spot makes it give up at once, without charging. A new building's hole in the navmesh is built asynchronously; until it is there, units whose path leads into the footprint wait at its edge, then route around it. A site whose builder leaves or dies stays as it is until a builder is sent to it again; several builders on one site add up. A `Build` order without units is placed directly by the server, but only while the cheat console variable `rts.DebugBuild` is on; the tests use that to place buildings quickly.

Every player starts with the game mode's `StartingCredits`; credits replicate to their owner only. Placing a building charges its `Cost`, and the server refuses what the player cannot afford, just as the client's ghost turns red. Cancelling an own construction site refunds the share still to be built, rounded down: half built returns half the cost. A construction site the enemy destroys refunds nothing. A completed supply depot brings one harvester, which loads at the nearest supply source, delivers to the nearest own depot and earns its load in credits, round after round. When its source runs dry it delivers what it carries and moves on to the nearest other source within its search radius, or goes idle.

Completed buildings add their `PowerOutput` to and take their `PowerDraw` from their owner's grid; construction sites count for nothing. While the draw exceeds the output the player is low on power: all production runs a third slower (construction, units and upgrades) and buildings flagged `bRequiresPower`, such as the test tower, hold fire. A faction with `bUsesPower` off is never low on power. Power, like credits, replicates to its owner only, and a team without a player is always fully powered.

A completed building whose data lists `Units`, such as the barracks or the vehicle factory, produces them. Queueing a unit charges its cost at once and is refused while the queue holds five, when the player cannot afford it or lacks one of its `Prerequisites` (completed own buildings, such as a supply depot for a harvester), and at a building still under construction. The front entry builds over its `BuildTime`, a third slower while low on power, then comes out at the building's front edge and walks to the rally point, which starts just ahead of it; a harvester then sets off for the nearest supply source from there. Cancelling takes the last queued unit of that kind off the queue and refunds its full cost, so progress on the front one is kept while a later one is left; a destroyed building takes its queue with it, unrefunded. The queue, its progress and the rally point replicate to every player; `Produce`, `CancelProduction` and `SetRallyPoint` are commands like any other.

A building's data can also list `Upgrades` to research, such as rifle training at the barracks. An upgrade goes through the same queue as a unit: charged on queueing, a third slower on low power, refunded in full when cancelled. Each player researches an upgrade once: one already researched, or waiting in the queue of any of the player's buildings, is refused. A finished upgrade joins the player's researched upgrades, which replicate to that player only, and multiplies its `Stat` (weapon damage or max health) by its `Multiplier` for every unit and building listed in its `Targets`: those standing at once and those spawned later. A max health upgrade keeps each one's share of health. The production menu shows an upgrade being researched and marks one researched as done.

The tech tree is the `Prerequisites` of each unit, building and upgrade: everything listed must be owned, a building once it is completed and standing, a unit while it lives, an upgrade once researched. In the test content the vehicle factory needs a barracks, the tower a power plant, the harvester a supply depot and the grenadier the barracks' rifle training, which makes infantry rifles deal half again as much damage. The builder's build menu and the production menu show an entry the player cannot have yet greyed out with what it needs, its placement ghost does not start, and the server refuses the `Build` or `Produce` order. Only new orders are checked: losing a prerequisite leaves units already queued, buildings already paid for (also those queued with Shift) and construction sites already placed to carry on. `RTSProduction::IsAvailable` is the pure check over a set of owned entries that the client and server share.

## Tests

`Tools/Scripts/ue.ps1 -Task build|test|setup` wraps the commands below and exits nonzero on failure. It uses `UE_ROOT` as the engine folder, falling back to `G:\Program Files\Epic Games\UE_5.6`.

```
"<UE_5.6>\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" "<repo>\WorldDivide.uproject" -ExecCmds="Automation RunTests WorldDivide;Quit" -unattended -nullrhi
```

`WorldDivide.Smoke.TestMap` plays `L_TestMap` in PIE and checks that a move order brings all 18 own units around the wall to the target while enemy units ignore it. `WorldDivide.Smoke.AttackOrder` orders a tank to attack an enemy out of range and checks it closes in and destroys it. `WorldDivide.Smoke.AttackMove` drives a tank past an enemy infantry beside its lane, in the tank's range but out of the rifle's: on a plain move it holds fire and the infantry stays untouched; attack-moving back it stops, destroys the infantry and then reaches its target. `WorldDivide.Smoke.AttackMoveBuilding` attack-moves three tanks past an enemy power plant and checks they destroy it before going on to the target. `WorldDivide.Combat.*` cover health and an unordered duel between two idle units. `WorldDivide.Buildings.*` cover grid snapping, construction over the build time, a finished tower killing enemies in range, an idle unit destroying an enemy construction site whose edge is in range, weapons preferring enemy units over buildings, and a builder's Build order being charged when given, refused when unaffordable, and refunded when dropped, stopped, refused on arrival or ended by the builder's death, while a builder sent aside keeps its payment, and a builder's order being refused without a completed own prerequisite, while one paid for before the prerequisite fell and resuming a site still start. `WorldDivide.Economy.*` cover credits, supply sources running dry, a completed depot spawning its harvester, and a full harvest run docked between a depot and a source: steady deliveries, the last partial load, moving on to the next source and stopping when none is in reach. `WorldDivide.Power.*` cover the efficiency calculation and the grid's totals, a powered tower going dark and construction slowing when the only plant falls and both recovering once a new plant completes, and a faction without power being unaffected. `WorldDivide.Production.*` cover the queue (charged on queueing; refused when full, unaffordable, not on the building's list, for another team, under construction or destroyed; units coming out in order, each one build time after the last), prerequisites (a missing, unfinished, enemy or destroyed building does not count; `IsAvailable` needs every listed entry and ignores empty ones), cancelling (full refund, progress kept unless the front entry goes) and production slowing on low power. `WorldDivide.Upgrades.*` cover research (only once per player: refused while queued at any own building or once researched, a destroyed building's queue releasing it, no unit spawned), cancelling (full refund, can be queued again), research slowing on low power, how multipliers combine, the effect on existing and newly spawned units and buildings (damage dealt, max health with its share kept, other units and the enemy unaffected) and an upgrade as a prerequisite. `WorldDivide.Economy.ConstructionRefund` covers the refund for cancelling a site, refused cancels of another team's site or a completed building, and no refund for a destroyed site. `WorldDivide.Smoke.BuildingPlacement` gives the player a power plant, checks that outside debug build there is no build menu without a builder and the server refuses a `Build` without units, and checks that client and server accept an open spot and reject spots on buildings, units, walls and off the navmesh, plus buildings outside the faction and buildings the player cannot afford, that placing charges the cost, and that the building completes after its build time and draws from the grid; it then selects and cancels a half-built site for half its cost and checks that enemy buildings cannot be selected or cancelled. `WorldDivide.Smoke.BuildPrerequisites` walks the test tech tree through the debug build menu: the tower needs a power plant, and the vehicle factory can neither start its ghost nor be placed until a barracks completes; once the barracks is destroyed a second factory is refused while the one placed completes. `WorldDivide.Smoke.BuilderConstructs` orders a builder to build a tower: the order is charged at once (an unaffordable one is refused, and a Stop or another order refunds orders not yet placed, queued ones included), nothing is placed until it stands at the site and placing charges nothing more, construction advances while it stays and holds once it walks away, a second builder resumes the site and construction holds again once that builder dies, the first builder finishes it and its order ends, and two buildings queued with Shift are both charged at once and built one after the other; a tank given a `Build` places and charges nothing, and a builder sent off the map and into a wall places nothing and is refunded. `WorldDivide.Smoke.BuilderClearsSite` checks that an enemy parked on the spot makes a builder drop its order and refunds it, and that an idle own tank and an own infantry on an attack order step off a tower's site, after which the builder places and finishes the tower and the infantry fires at its target again. `WorldDivide.Smoke.Harvest` buys a supply depot beside a source holding three loads and checks its harvester delivers each load in steady cycles, then goes idle. `WorldDivide.Smoke.Production` selects a barracks, sets its rally point and queues three infantry through the controller, plus a fourth it cancels for a refund, and checks that they come out one build time apart and each reaches the rally point. `WorldDivide.Smoke.ProducedHarvester` has a vehicle factory produce a harvester and a tank: the harvester walks to the rally point and then delivers a load from the nearby source, while the tank stays at the rally point. `WorldDivide.Smoke.UpgradeResearch` selects a barracks and researches rifle training through the controller: it is charged once and refused while queued and once researched, an infantry already standing and one produced afterwards deal the upgraded damage, and the grenadier is refused before the research and accepted after it. `WorldDivide.Smoke.RouteAroundBuilding` places a building across a tank's path and checks the tank walks around it. `WorldDivide.Smoke.BuildingOnPath` places a building just in front of a tank driving across its spot and checks the tank waits outside the footprint until the navmesh hole is built, while a tank on another lane drives on, and then walks around it to its target. `WorldDivide.Smoke.AttackBuilding` orders three tanks to attack an enemy power plant and checks they destroy it and its hole in the navmesh closes. `WorldDivide.Smoke.SolidObstacles` checks that no navmesh lies inside or on top of the map's walls and blocks, while the ground beside them stays walkable. `WorldDivide.Smoke.MoveIntoObstacle` sends three tanks onto the roof of a block and checks they stop at its edge on their own side instead of dropping the order. `WorldDivide.Smoke.ListenServer` plays `L_TestMap` as a listen server with one client, checks both players' teams and start spots and that each sees only its own credits, and sends a move for every unit from the client's controller: the server moves only the client's units and the client sees them arrive. The client sends its builder to buy a construction site and sees its credits drop before the site is placed, stops the builder and cancels the site: the site disappears on both sides and the client sees its refund while the host's credits stay put. The server then gives the client a barracks: the client sets its rally point, queues two infantry and sees them charged, cancels one and sees the refund, and sees the other come out and reach the rally point. At the same barracks the client researches rifle training: it sees the charge and the upgrade queued, then researched, while the host's controller and player state stay without it, and only then may it queue the grenadier the upgrade unlocks. The client then orders its units to attack a host building and must see its health drop before it disappears. Last, the client attack-moves a tank past a host infantry and must see the infantry disappear and the tank arrive.

Idle units fire at the nearest enemy in range on their own, enemy units before enemy buildings; units on a move order hold fire. Units on an attack-move engage the same way: they stop while an enemy is in range and walk on once none is left. A move into a wall or a building ends at its edge on the unit's side. Weapon range is measured to the edge of a target's footprint.

To rebuild the test content after changing `setup_testmap.py` or a data asset class, run `ue.ps1 -Task setup` (after `-Task build`), or directly:

```
"<UE_5.6>\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" "<repo>\WorldDivide.uproject" -run=pythonscript -script="<repo>\Tools\Editor\setup_testmap.py" -unattended -nullrhi
```

Setup only saves assets that differ from the script: data assets are compared property by property, and the materials, the imported models and `L_TestMap` store a hash of the code and source files that build them and are rebuilt only when those change. A run without script changes writes nothing and leaves `git status` clean.

Because the assets are LFS lockable, Git LFS checks them out read-only. If setup has to rewrite one, it writes nothing and `ue.ps1` exits 3 listing the files. Then:

1. `git lfs lock <file>` for each listed file
2. rerun setup, commit and push
3. `git lfs unlock <file>`
