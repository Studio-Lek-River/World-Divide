# World Divide

A real-time strategy game in the spirit of C&C Generals Zero Hour, built in Unreal Engine 5.8. Gameplay logic is C++; content and UI go in Blueprint and data assets. Nothing is taken from Generals itself: no names, art, audio, UI or code.

## Requirements

- Unreal Engine 5.8
- Visual Studio 2022 with the "Game development with C++" workload
- Git LFS (`git lfs install` once per machine) — all `.uasset`/`.umap` files live in LFS and are lockable

## Getting started

1. Clone, then right-click `WorldDivide.uproject` → *Generate Visual Studio project files*, or just open the `.uproject` and let it build.
2. The editor opens `L_TestMap`, a sandbox where team 1 stands still. Press **Play**.
3. To play a skirmish, open `Content/Maps/L_MainMenu` and press **Play**, or start the game outside the editor, where it opens on the main menu. **Skirmish** opens the lobby on your own, **Host game** opens it for others to join, and **Join game** joins a host by address (`127.0.0.1` on the same machine). In the lobby the host picks the map, sets each seat open, closed or to an AI of Easy, Normal or Hard, and picks each seat's base; every player can pick its own base. **Start** takes everyone to the chosen map (`L_Skirmish` or the two-base `L_SkirmishDuel`). To try it with two players in the editor, open `L_Lobby` and play as a listen server with 2 players (*Play → Net Mode: Play As Listen Server*), or open `L_MainMenu` with 2 standalone players and host in one window and join in the other.
4. `L_Skirmish` opened directly plays you against a Normal AI. The `?Seats=` URL option sets the seats instead, one per team, comma-separated: `Open`, `Closed`, `Human`, or `AI` with an optional difficulty (`AI-Hard`), each with an optional base after `@`, for example `open L_Skirmish?Seats=Open@3,AI-Hard@0` in the console.

Command-line build:

```
"<UE_5.8>\Engine\Build\BatchFiles\Build.bat" WorldDivideEditor Win64 Development -Project="<repo>\WorldDivide.uproject" -WaitMutex
```

## Controls

| Input | Action |
|---|---|
| WASD / arrow keys / screen edge | Pan camera |
| Mouse wheel | Zoom |
| Q / E, or drag with middle mouse | Rotate camera |
| Left click / left drag | Select own units (Shift adds or toggles); a click on an own building selects that building |
| Delete, or the HUD's cancel button | Cancel the own construction site under the cursor, or else the selected one, for a refund; with a production building selected, cancel the last entry in its queue |
| Right click | Move, attack when on an enemy unit or building, harvest when on a supply source, or resume an own construction site with builders (Shift queues); with a production building selected, set its rally point |
| X, or Stop in the command panel | Stop |
| Space | Centre the camera on the latest attack warning, for up to 20 seconds after it |
| J or Attack-move in the command panel, then left click | Attack-move: walk to the clicked spot, stopping to fight enemies that come into range on the way (Shift queues and keeps attack-move armed); right click or Esc cancels |
| The hotkey shown on the button (1–9 by default), or a click on its card in the command panel | With a builder selected: place that building; the builder walks there, places it and builds it. With `rts.DebugBuild 1` in the console and no builder selected: place that building of your faction directly. A greyed card says why it is not available |
| The hotkey shown on the button (1–9 by default), or a click on its card in the command or upgrades panel | With a production building selected: queue that unit or research that upgrade; a click on a queued entry in the selection panel cancels it for a refund |
| Left click / right click or Esc | While placing: build (Shift queues it and keeps placing) / cancel (Esc also stops PIE in the editor) |
| 1, or a click on its launch entry in the HUD, then left click | With an own superweapon selected that is ready: launch it at the clicked spot; right click or Esc cancels |
| A click on the HUD's restart button | Once the match is over, on the host: restart the match on the same map, clients included |

Every player order is an `FRTSCommand` sent through `ARTSPlayerController::Server_IssueCommand` and executed only on the server, so singleplayer already runs the multiplayer code path. On the server every order, a player's or the AI's, goes through `RTSCommands::Issue`, which refuses it once the match is over and checks it against the issuing player. Units and buildings are always relevant for now; fog of war will decide relevancy later.

Buildings snap to a 100 cm grid. R turns the ghost a quarter turn; a turned building's footprint swaps its sides on odd turns and stays axis aligned, so snapping, blocking, the navmesh hole, range and approach all follow the turned footprint (`RTSBuildPlacement::GetRotatedFootprint`, `ARTSBuilding::GetFootprint`), and the turn travels in the `Build` order. Shift on the confirming click keeps placement on for the next building. The client's ghost and the server run the same placement check (no overlap with units, buildings or obstacles; footprint on the navmesh), which is why clients keep a navmesh too (`bAllowClientSideNavigation`). Buildings own builders were ordered to place but have not placed yet, Shift-queued ones included, replicate as each builder's planned sites: the ghost turns red over them and the server refuses a new order overlapping one, uncharged, so the earlier order keeps its spot (`RTSBuildPlacement::OverlapsPlannedSite`). Builders place buildings: a `Build` order sends the builder to a spot just outside the footprint, where it places the building (after the same checks) and constructs it for as long as it stays. The building is paid when it is ordered, also when queued with Shift, and refused when the player cannot afford it or lacks one of its prerequisites; an order that ends before its building is placed (stopped, replaced, unreachable or blocked spot, builder killed) is refunded in full. Own units standing on the spot when the builder arrives step aside to the nearest free spot outside the footprint, then pick up their own orders again; the builder places the building once the spot is clear, or gives up after 5 seconds. That is why a builder's ghost stays green over own units, while the debug ghost, placing without a builder, turns red over any unit. An enemy unit, a building or an obstacle on the spot makes it give up at once, without charging. A new building's hole in the navmesh is built asynchronously; until it is there, units whose path leads into the footprint wait at its edge, then route around it. A site whose builder leaves or dies stays as it is until a builder is sent to it again; several builders on one site add up. A `Build` order without units is placed directly by the server, but only while the cheat console variable `rts.DebugBuild` is on; the tests use that to place buildings quickly.

Every player starts with the game mode's `StartingCredits`; credits replicate to their owner only. Placing a building charges its `Cost`, and the server refuses what the player cannot afford, just as the client's ghost turns red. Cancelling an own construction site refunds the share still to be built, rounded down: half built returns half the cost. A construction site the enemy destroys refunds nothing. A completed supply depot brings one harvester and produces more, so a lost one needs no vehicle factory. A harvester loads at the nearest supply source, delivers to the nearest own depot and earns its load in credits, round after round. When its source runs dry it delivers what it carries and moves on to the nearest other source within its search radius, or goes idle.

Completed buildings add their `PowerOutput` to and take their `PowerDraw` from their owner's grid; construction sites count for nothing. While the draw exceeds the output the player is low on power: all production runs a third slower (construction, units and upgrades) and buildings flagged `bRequiresPower`, such as the test tower, hold fire. A faction with `bUsesPower` off is never low on power. Power, like credits, replicates to its owner only, and a team without a player is always fully powered.

A building whose data has a `SuperweaponChargeTime`, such as the test superweapon, charges once it completes, and its charge holds outright while the owner is low on power. Its countdown, and whether low power holds it, replicates to every player, and every HUD lists each superweapon's countdown in its team's colour. When one completes, the other teams' players are warned that an enemy superweapon was built; when it is charged they are warned that it is ready, and its own players that theirs is. With an own ready superweapon selected, 1 or its launch entry arms targeting and a left click sends `LaunchSuperweapon`, a command like any other: the server refuses it for another team's building, before the charge is done, while a strike is on its way and once the match is over. The strike lands `SuperweaponDelay` later, while every player sees a ring at the target, and the charge starts over at launch. It deals `SuperweaponDamage` at the target, falling off linearly to `SuperweaponEdgeDamage` of it at `SuperweaponRadius` and nothing beyond (`RTSSuperweapon::ComputeFalloffDamage`), to every unit on the ground by its centre and every building by the nearest point of its footprint, of any team, the owner's included; aircraft in flight are out of it. A superweapon destroyed before its strike lands takes the strike with it. The test superweapon needs a vehicle factory, one per team, charges for two minutes and strikes three seconds after launch with 1500 damage over 15 m.

A completed building whose data lists `Units`, such as the barracks, the vehicle factory or the supply depot, produces them. Queueing a unit charges its cost at once and is refused while the queue holds five, when the player cannot afford it or lacks one of its `Prerequisites` (completed own buildings, such as a supply depot for a harvester), and at a building still under construction. The front entry builds over its `BuildTime`, a third slower while low on power, then comes out at the building's front edge and walks to the rally point, which starts just ahead of it; a harvester then sets off for the nearest supply source from there. Cancelling takes the last queued unit of that kind off the queue and refunds its full cost, so progress on the front one is kept while a later one is left; a destroyed building takes its queue with it, unrefunded. The queue, its progress and the rally point replicate to every player; `Produce`, `CancelProduction` and `SetRallyPoint` are commands like any other.

A building's data can also list `Upgrades` to research, such as rifle training at the barracks. An upgrade goes through the same queue as a unit: charged on queueing, a third slower on low power, refunded in full when cancelled. Each player researches an upgrade once: one already researched, or waiting in the queue of any of the player's buildings, is refused. A finished upgrade joins the player's researched upgrades, which replicate to that player only, and multiplies its `Stat` (weapon damage or max health) by its `Multiplier` for every unit and building listed in its `Targets`: those standing at once and those spawned later. A max health upgrade keeps each one's share of health. The production menu shows an upgrade being researched and marks one researched as done.

Every team with a `PlayerStart` tagged `Team<id>` starts with its faction's `Headquarters` there, completed, spawned by the game mode when play starts: the test headquarters produces the builder. The headquarters is also on the faction's and the builder's build lists, so builders can rebuild a lost one. A building's `MaxCount` limits how many a team may own at once, construction sites included; the test headquarters has a limit of one. The build menu shows an entry at its limit greyed out, its ghost does not start, and the server refuses the order uncharged. The server checks the limit again when a builder places its site, so a second order paid for while another builder walked to its own site is refunded like a blocked spot. `RTSProduction::IsAtBuildLimit` is the check the client and the server share. A team that lost its headquarters stays in the match only while another building that is not a defence stands; its builders can then rebuild it. A team stays in the match while it has a building that is not a defence (`bIsDefense`, such as the tower), construction sites included; once its last one is destroyed or cancelled, it is out. When a team drops out and one is left, the match is over: that team wins, every other one loses, the game state replicates the result, each player's HUD shows a Victory! or Defeated! pop-up in place of the menus, and the server refuses every order from then on. The simulation stops with it: units stand where they are and hold fire, towers hold fire, harvesters and builders pause, and construction and production queues hold their progress; the camera keeps working. The host's pop-up offers a restart, which reloads the map for every player; clients wait for it.

The tech tree is the `Prerequisites` of each unit, building and upgrade: everything listed must be owned, a building once it is completed and standing, a unit while it lives, an upgrade once researched. In the test content the vehicle factory needs a barracks, the tower a power plant, the harvester a supply depot and the grenadier the barracks' rifle training, which makes infantry rifles deal half again as much damage. The builder's build menu and the production menu show an entry the player cannot have yet greyed out with what it needs, its placement ghost does not start, and the server refuses the `Build` or `Produce` order. Only new orders are checked: losing a prerequisite leaves units already queued, buildings already paid for (also those queued with Shift) and construction sites already placed to carry on. `RTSProduction::IsAvailable` is the pure check over a set of owned entries that the client and server share.

A skirmish map such as `L_Skirmish` uses `ARTSSkirmishGameMode`, which plays a list of seats, one per team: the seat's index is the team id, which also gives the team its colour. A seat is `Open` (the first player to join without a seat of its own takes it), `Human` (held by a player from the lobby), `AI` with a difficulty, or `Closed`, and has a start spot, the `PlayerStart` tagged `Team<spot>` its team plays from; a seat without one gets a random free spot when the match loads. The seats come from the `Seats` URL option, else the game mode's defaults: an open seat at spot 0 against a Normal AI at spot 1, the other two closed. A played seat gets its faction's headquarters at its spot, and the starting units the map places at a spot go to the team playing from it; a closed seat and a spot nobody plays get nothing. A player who joins with no seat left is refused. The lobby (`L_Lobby`, `ARTSLobbyGameMode`) offers the maps listed in `SkirmishMaps` of the World Divide settings, each a `URTSMapData` with its start spots and default seats, and starts on the first; the test maps `DA_MapSkirmish` and `DA_MapDuel` are not among them, the lobby smoke tests swap them in (`RTSTests::FRTSUseTestLobbyMaps`). Its seats, one per start spot, are the map's defaults with the closed seats open. When the host picks another map the seats resize to its start spots: the seats it still has are kept, a human beyond them takes the first seat no human holds, a base the map lacks goes back to random, and every player but the host readies up again (`RTSSkirmish::ResizeSeats`); a map with fewer spots than humans is refused. Each player who joins takes the first open seat, and one who leaves opens it again. A player refused at the door lands on the main menu with the reason, such as "The lobby is full", and when the host leaves the lobby its players land there with "The host closed the lobby". The host sets a seat that no player holds open, closed or to an AI of a difficulty, and the base of any seat; each player sets the base of its own seat, and no two seats share a base. The seats replicate to every player; changes go to the server as RPCs of `ARTSLobbyPlayerController`, which checks them against the same rules (`RTSSkirmish::CanChangeType`, `CanChangeStartSpot`). Start, once a human and one more player or AI hold a seat, travels everyone to the chosen map with the seats in the `Seats` option; open seats nobody took are closed. Each player gets a random token with its lobby seat, kept by its `URTSLocalPlayer` and sent with its login to the match (`?SeatToken=`), so the match gives every player the seat it held in the lobby, whatever order they reconnect in. Other players see the seats but not the tokens. The host's restart after a match travels to the same map with the same seats and bases.

An AI seat gets an `ARTSAIPlayer` when play starts, a player without a connection whose player state gets the seat's team, the default faction and the starting credits like a human's, and the seat's difficulty. Once a second it follows its faction's `AIBuildOrder`, issuing its orders through `RTSCommands::Issue` and paying for them from its own credits. It works on the first step it does not own enough of yet, waiting for the credits rather than skipping ahead: an idle builder places the next building on a ring around its headquarters (a depot beside the nearest supply source), keeping 3 m from other buildings and the exits of its production buildings, and the building that offers the next unit or upgrade with the shortest queue queues it. A step lost again, such as a destroyed building, comes first once more. Once every step is met it keeps two army units queued at each production building. It sends idle builders to finish sites no builder is working on and idle harvesters back to work, and points the rally point of each building that produces army units 15 m ahead of its headquarters, towards the nearest enemy building; a depot keeps its own, so its harvesters set off for the nearest source. A wave goes once the army, its armed units other than builders and harvesters, reaches the wave size, or once the wave interval has passed with at least the minimum size: the army attack-moves to the enemy building nearest it, and moves on to the next one once there is nothing left to fight. While an enemy unit is within 25 m of one of its buildings no wave goes: the army, and wave units still within that distance, which rejoin the army, attack-move to the enemy unit nearest its buildings, and once none is left each goes back to the gather point when its own fight is over. The difficulty multiplies the interval and the sizes, from the build order's `DifficultyScales`; in the test content Easy waits half again as long with waves half the size, Hard comes in two thirds of the time with waves half again as large. The AI sees what every player sees, all units and buildings, since there is no fog of war yet; it must read the same visibility once there is. `L_TestMap` uses the plain game mode, so its team 1 has no player.

Idle units fire at the nearest enemy in range on their own, enemy units before enemy buildings; units on a move order hold fire. To rebuild the test content after changing `setup_testmap.py` or a data asset class, run `ue.ps1 -Task setup` (after `-Task build`), or directly:

```
"<UE_5.8>\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" "<repo>\WorldDivide.uproject" -run=pythonscript -script="<repo>\Tools\Editor\setup_testmap.py" -unattended -nullrhi
```

Setup only saves assets that differ from the script: data assets are compared property by property, and the materials, the imported models and `L_TestMap` store a hash of the code and source files that build them and are rebuilt only when those change. A run without script changes writes nothing and leaves `git status` clean.

Setup runs without a renderer, so it draws the lobby's map previews from the obstacles and supply sources. `ue.ps1 -Task setup -Render` (a GPU is needed; it passes `-AllowCommandletRendering` instead of `-nullrhi`) renders them top-down from the levels instead. A run without a renderer keeps a rendered preview as long as its level is unchanged; after a level change, rerun with `-Render` before committing. `WorldDivide.Maps.PreviewCameraAlignment` checks that the render camera puts every start spot where the lobby draws its marker.

Because the assets are LFS lockable, Git LFS checks them out read-only. If setup has to rewrite one, it writes nothing and `ue.ps1` exits 3 listing the files. Then:

1. `git lfs lock <file>` for each listed file
2. rerun setup, commit and push
3. `git lfs unlock <file>`
